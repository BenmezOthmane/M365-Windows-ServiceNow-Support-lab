# INC001 — Outlook / Email Connectivity Issue

## Incident Summary

**User:** `hr.sara`  
**Category:** Email  
**Subcategory:** Outlook  
**Impact:** Medium  
**Urgency:** Medium  

**Issue:** Outlook could not reliably access Microsoft 365 services.

The issue was investigated on `WIN-USER-01` using a controlled lab troubleshooting workflow.

---

## 1. Baseline

Initial connectivity testing showed that the endpoint could not resolve the Microsoft 365 Outlook hostname.

```powershell
Test-NetConnection outlook.office365.com -Port 443
```
The test returned:
```WARNING: Name resolution of outlook.office365.com failed```

![baseline-dns-failure](screenshots/M365/01-baseline-dns-failure.png)

## 2. Investigation

The endpoint network configuration was inspected.
WIN-USER-01 was configured with:
```
IPv4 Address : 192.168.50.21
Gateway      : 192.168.50.1
DNS          : fec0:0:0:ffff::1
               fec0:0:0:ffff::2
               fec0:0:0:ffff::3
```
![incorrect-dns-configuration](screenshots/M365/02-incorrect-dns-configuration.png)
![dns-resolution-failure](screenshots/M365/03-dns-resolution-failure.png)
![dns-server-connectivity](screenshots/M365/04-dns-server-connectivity.png)
![direct-dns-resolution](screenshots/M365/05-direct-dns-resolution.png)

The configured DNS servers were not the DNS server used by the lab's Active Directory environment.
DNS resolution of the internal domain controller also failed:

```powershell
nslookup dc01.genitech.lab
```

Result:
No response from server

## 3. Root Cause Identification
Connectivity to the intended DNS server was tested directly:

```powershell
Test-NetConnection 192.168.50.5 -Port 53
```
The result confirmed that the endpoint could reach the DNS service on DC01.
```
TcpTestSucceeded : True
```
A direct DNS query against DC01 also succeeded:
```powershell
nslookup dc01.genitech.lab 192.168.50.5
```
```
Name:    dc01.genitech.lab
Address: 192.168.50.5
```
## 4. Remediation
The endpoint DNS configuration was corrected to use the Active Directory DNS server:
```powershell
Set-DnsClientServerAddress `
    -InterfaceAlias "Ethernet0" `
    -ServerAddresses 192.168.50.5
```
The configuration was verified:
```DNS Servers : 192.168.50.5```

![dns-configuration-fixed](screenshots/M365/06-dns-configuration-fixed.png)

## 5. Validation
The final validation was performed using an actual email exchange between lab accounts.

A test email was sent from another user account and successfully received in Outlook.

This confirmed that normal email communication had been restored.

![outlook-service-restored](screenshots/M365/10-outlook-service-restored.png)

## Resolution

- Root Cause: Incorrect DNS configuration on WIN-USER-01.

- Resolution: Configured the endpoint to use the Active Directory DNS server 192.168.50.5.

- Validation: Successful test email delivery confirmed restored email communication.

- Status: Resolved
